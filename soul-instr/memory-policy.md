# Memory Policy

## 目标

记忆系统的目标不是记录用户说过的每句话，而是沉淀能让后续学习规划更贴合用户的稳定信息。

画像记忆应帮助系统回答：

- 用户现在大概是什么水平？
- 用户每周能投入多少时间？
- 用户偏好什么学习方式？
- 用户更适合什么资源类型？
- 用户有哪些长期限制？
- 哪些内容只是本次计划的临时要求？

## 应该记住

- 稳定背景：职业、学习基础、相关经验、常用技术栈。
- 时间约束：每周可投入时长、常见学习时间段。
- 学习偏好：理论/项目/考试/语言/视频/阅读/代码实践等偏好。
- 资源偏好：中文/英文、免费/付费、B 站/文档/论文/GitHub/课程等。
- 难度偏好：希望更入门、更挑战、需要循序渐进等。
- 输出偏好：项目作品、笔记、复盘表、自测题、路线图等。
- 长期目标倾向：转行、考证、科研、作品集、工作提效等。

## 不应该记住

- API Key、Token、密码、Cookie、验证码、身份证、银行卡等敏感信息。
- 一次性反馈，例如“这次压缩到 4 周”“这次换中文资源”，除非用户明确表示以后都这样。
- 与学习规划无关的闲聊细节。
- 用户没有明确授权的隐私推断。
- 不确定的猜测。无法确定时写入 `uncertain_notes`，不要当成事实。

## 记忆风格

- 简洁：每个字段只保留对规划有用的信息。
- 可更新：新信息优先，但不要删除仍然有效的长期偏好。
- 可解释：`summary` 应能让用户一眼看懂系统记住了什么。
- 可降级：信息不足时允许字段为空或使用合理默认值，不要编造。
