# Memory Merge Rules

## 信息优先级

画像合并时按以下优先级处理：

1. 用户本轮明确回答
2. Web 设置中的全局记忆
3. 历史画像
4. 模型根据目标做出的低置信推断

高优先级信息可以覆盖低优先级信息，但要保留仍然有效的稳定偏好。

## 合并策略

- `level`：本轮回答优先。如果用户说“刚入门/零基础”，应覆盖历史更高水平。
- `weekly_hours`：本轮明确时间优先。没有新时间时保留历史。
- `preferences`：合并去重，保留稳定偏好。
- `resource_preferences`：合并去重；资源类反馈只有在用户说“以后都...”时才沉淀为长期偏好。
- `constraints`：合并长期约束；临时计划限制放入 `temporary_context`。
- `temporary_context`：只记录本轮计划特定要求，例如“这次 4 周内完成”。
- `uncertain_notes`：只放低置信内容，不参与强约束。

## 避免错误记忆

- 不要因为用户这次要求“换成中文资源”，就永久认为用户只接受中文资源。
- 不要因为一个股票投资计划，就推断用户长期从事金融行业。
- 不要把“目标不是短线暴富”写成用户价值判断，只写成当前学习目标约束。
- 不要把模型搜索到的资源当作用户偏好。

## 输出检查

保存画像前，确认：

- 是否包含 API Key 或密钥？如果有，删除。
- 是否把临时反馈写成长期偏好？如果有，移到 `temporary_context`。
- 是否缺少 `summary`？如果缺少，补一句简洁总结。
